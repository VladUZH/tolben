Tolben

The gate playground

Tolben proposes clearer rewrites of finished sentences using a small local model, and shows one to the writer only when a deterministic gate cannot find a way it changed the meaning. The gate refusing is the claim the whole product rests on, so this page hands it to you: the real modules from src/, bundled unchanged and running in your browser.

There is no model on this page, because a browser cannot run one. Everything here is either deterministic code you are executing yourself or a recording of a benchmark run that has already happened. Nothing is sent anywhere: the page loads four JSON files from its own directory and makes no other request, so it works with the network off.

Add to Obsidian

Put main.js, manifest.json and styles.css from a release of VladUZH/blue-underline into <vault>/.obsidian/plugins/tolben/, then enable Tolben under Settings → Community plugins with Restricted Mode off. The plugin provisions its own model server and downloads nothing until you say so.

Desktop only

The plugin's manifest sets isDesktopOnly. It runs a small model server on loopback and talks to it over HTTP, and Obsidian mobile has nowhere to run one. Read this page here; add the plugin from a desktop.

The deterministic tiers, live

Type below. When a sentence ends in a full stop, a question mark or an exclamation mark, that sentence — and only that sentence — is analysed. Words the tiers would change get a blue underline; hover or click one for the proposed sentence and the reason. Each underline carries the name of the tier that produced it.

The model tier is not running here. In the plugin, a local Qwen3.5-2B proposes most of the rewrites a writer sees, and the two tiers below are the floor beneath it: mechanical repairs, and a small table of first-party clarity rules. Those two are all you are watching. A sentence that gets no underline on this page is not a sentence Tolben has nothing to say about; it is a sentence the cheap tiers had nothing to say about.

    Put a rewrite to the gate

    This is the part worth being sceptical about. Give the gate a sentence and a proposed rewrite of it — one of the pairs below, or anything you care to type — and the page runs the real acceptance policy: validateRewrite from src/safety.mjs, then the deletion policy in src/pipeline.mjs. The verdict you get is the verdict the plugin would reach, because it is the same code reaching it.

    A setting in the plugin: terms the writer has declared must survive a rewrite verbatim. Most people never set one, and with the box empty this page runs the gate exactly as a default install would. Tolben also detects some tokens by shape on its own, but not all of them — --force is one it does not, and the difference is easy to see by putting it here and running the pair twice.

    The engine is stubbed, because there is nothing here for it to do: it returns your rewrite verbatim, with “shorter” as the model's stated reason, which is the stub bench/corpus/torture.json is scored under. The two deterministic tiers are switched off, so a mechanical repair or a fired clarity rule cannot answer for the sentence before the gate is reached. What is left is the gate.
